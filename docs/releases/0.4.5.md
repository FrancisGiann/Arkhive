# Arkhive 0.4.5 — original Discover design and reader fixes

Universal Android debug preview, minimum Android 8/API 26. Install over the existing preview to retain data; package and signing certificate are unchanged. Internal version **0.4.5-1**, version code **12**, package `dev.francisgiann.readingapp.dev`.

## Changes

- Restored the approved full-width Discover panel with rounded top corners below the title cover. Its tap opens actual related category/genre catalog results, with context, filters and Back to the title. Synopsis/tags remain below Discover and before Chapters.
- Improved long-title wrapping at narrow widths and enlarged text. Whole words remain intact, visible text is bounded with ellipsis, and the complete accessible title is retained.
- Centered online-novel loading and error status inside the reading area, clear of the measured header/footer controls, without shifting the loaded passage.
- Made exact-origin review accept pasted HTTPS page/source URLs, preview the canonical host/port, and offer the matching source's observed blocked cover host for explicit selection. Existing HTTPS/network restrictions and the separate Trust confirmation remain intact.
- Retained 0.4.4 theme consistency, per-title paper preferences, shelf behavior and reader center-tap improvements.

Category/genre catalog relevance is not item-specific similarity ranking. Unsupported metadata/rankings are not fabricated.

## Validation and limits

- All **14 focused JVM tests passed** (discovery 3, library tools 5, reader status 2, origin normalization 4).
- API 35 x86_64 emulator checks verified final Light/Dark panel appearance, contextual Discover/Back, and the exact long-title whole-word fix at about274dp width/130% font, including the complete accessible title.
- Loading/loaded/actual empty-source error/Retry bounds and Pages/Continuous center-tap passage preservation passed before the final unrelated panel styling adjustment. Those unchanged reader paths were not redundantly rerun afterward.

The authored exact-origin fixture verified explicit observed-host selection, Cancel leaving permissions unchanged, and the rendered HTTP rejection with a greyed-out Trust control after ordinary dialog scrolling. HTTPS preview, persisted Trust and cover retry were **not completed end to end**: the automation inspected the text label rather than the disabled button's semantics, and a no-code-change debugger hold failed to attach. The four origin-normalization unit tests passed; they do not replace this unfinished UI check. No real extension permissions were changed.

These are scoped checks, not a passing full Android suite. Physical ARM devices, API26/36 runtime, full TalkBack, long-session battery and measured120fps remain unverified. The inherited webtoon reader may reset pixel offset within a tall image after recreation.
