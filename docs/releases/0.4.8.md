# Arkhive 0.4.8 — provider startup recovery and reader verification

Universal Android debug preview. Internal version **0.4.8-1**, version code **15**, package `dev.francisgiann.readingapp.dev`. Android 8/API26 or later. Install over the existing preview with the same package and signing certificate to retain data.

## Changes

- Repairs isolated JavaScript startup after leaving or cancelling a provider support check. Pending provider creation remains owned until completion; abandoned connections close before another bind, preventing the reported “Binding to already bound service” state.
- Retains fresh isolated execution, explicit extension/origin review, HTTPS restrictions and operation limits. No in-process fallback or automatic trust.
- Includes the reviewed 0.4.7 reader gesture/tile-viewport changes and compact outlined Explore action, with the approved rounded Discover panel retained.
- Adds partial zoom-out while still magnified followed by forward/reverse scrolling coverage in Long strip, Continuous vertical and Vertical pager.

## Verified

Seven focused JVM lifecycle tests and six scoped Android runtime methods passed on API35 x86_64. The cancellation/reconnect test reproduced the exact startup error on frozen0.4.7 and passed on0.4.8. Repeated provider use, CPU-timeout recovery and explicit trust/origin UI flow passed using authored fixtures.

The reader cases passed native zoom-in, partial zoom-out and forward/reverse scrolling while still magnified, plus return-to-fit/below-fit checks. Twenty-one actual external frame captures showed painted fixture content without a black frame in the covered sequence. Trust UI automation was corrected to scroll long dialog content into view, inspect the actual clickable control and match the displayed normalized-origin label; production trust policy was unchanged.

Physical-phone behavior remains unverified. These are synthetic scoped checks, not a full Android suite or a guarantee for every community source. Detailed artwork sharpness, sustained frame rate/battery and other Android/API/architecture runtimes remain unverified. Kol Novel's `invalid source filter: genre[]` remains reference-only and is not fixed.
